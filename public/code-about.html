Code Index for RAG

Point it at a code graph and ask about the code in English. Imports, calls, members, reverse dependencies. Ask a follow-up with “it” and it still knows what you meant.

What it demonstrates

This is retrieval over a codebase without an embedding model. The graph carries typed edges, and a question resolves to a walk over them.

The page opens on a demo graph built from a small fixture app that ships in the repository. You can open your own graph file, or point it at a repository.

The left panel lists the facts around whatever term is in focus. The right panel is the conversation, with suggested follow-up questions underneath.

The thing to demonstrate is the follow-up. Ask what talks to a module, then ask “what calls it?” without naming anything. The pronoun binds to the last resolved answer. Ask the same question cold and it tells you the pronoun resolved to nothing.

Chat you can replay

The first exchange below was captured by running the command line against the fixture app in this repository. The rest are assertions in the tool-layer test file.

Two turns, one pronoun. The trace lines are the engine's own.

tmct> what talks to store.mjs?
src/handlers/tasks.mjs and src/handlers/users.mjs.
Goal (inferred): Understand a dependency/usage relationship (imports and/or calls).
Canonical: uses "store.mjs" — reverse(uses, "store.mjs")
tmct> what calls it?
src/handlers/tasks.mjs.
Goal (inferred): Understand a call relationship.
Canonical: calls "it" — reverse(calls, "it")

Captured by running tmct chat --repo examples/mini-webapp --ephemeral in this repository.

A yes/no question answers with the edge it found, named.

tmct> does myFile import logging
Yes — imports edge from myFile.mjs to src/logging.mjs.

Asserted as an exact string in test/tools/ask.test.mjs.

Direct and transitive are different questions, and it treats them that way.

tmct> which modules import logging
myFile.mjs, src/someOtherFile.mjs
tmct> which modules transitively import logging
myFile.mjs, src/someOtherFile.mjs, app/entrypoint.mjs
traversal: reverse dependency closure

Asserted in test/tools/ask.test.mjs. The two hop result is the extra one.

When a class has no recorded members, it moves up to the module rather than claiming nothing calls it.

tmct> who calls Router
it refines up to the containing module rather than answering "nothing"

Asserted in test/tools/ask.test.mjs. A false “nothing calls it” would be a confident wrong answer, which is the thing this project is built to avoid.

What it works out

What the graph carries. Typed edges, not text similarity: imports, calls, defines, tests, touches, contains, inherits, callsSymbol, touchesSymbol, plus a derived co-change edge.

How a question resolves. Four steps. Parse the sentence into a query. Resolve the terms in it against the graph. Walk the edges. Render the answer. Each step can decline, and a decline produces a miss.

The walk handles more than one hop. It does forward relations, reverse closures for a transitive question, negation (“which modules do not import logger”), superlatives, and set anaphora, so “count them” after a list works.

How the thread is carried. The session keeps the last resolved subject as a standing focus and passes it into every question. A pronoun binds to that focus. With no focus behind it, the pronoun resolves to nothing and the engine reports that, rather than picking whatever was nearest.

What the vocabulary comes from. The graph's classes are SEON's code ontology: module, class, attribute, method. That is why a question like “what is a module” resolves against the same store as a question about your own code.

  • src/handlers/tasks.mjs calls store.mjs
  • Router rdf:type Class

How it is built

src/domain/codegraph.mjs parses entities into an in-memory graph. src/adapters/graph-build.mjs builds those entities from a repository.

src/domain/ask.mjs is the question grammar and the traversal. It is the same module every other page's ask box goes through.

scripts/build-demo-graph.mjs builds the deployed page's graph from a real committed fixture, examples/mini-webapp/.tmct/graph.json, and merges in the schema documents so vocabulary questions resolve too.

src/services/code-explorer-viz.mjs renders the page. The desktop shell builds the identical page from the same function; the only difference on the web is a link back to the desktop build.

src/tools/ exposes the same engine as a tool surface, which is what test/tools/ask.test.mjs exercises: 125 assertions in about 0.4 seconds.
