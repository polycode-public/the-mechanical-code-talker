tmct The Mechanical Code Talker — a pure-JS, no-LLM, offline, $0 chatbot

A chatbot in the ELIZA/PARRY lineage, obsessed with software the way PARRY was obsessed with the mafia. No model calls anywhere. Interpretation is mechanical, memory is an OWL-labelled graph on disk, and every answer is either grounded or an honest miss.

Install & quickstart

npm install -g @polycode-projects/the-mechanical-code-talker

$ tmct
tmct> what talks to the payment module?
…
tmct> which modules do not import logger?
…
tmct> /memory        # inspect what tmct remembers, with provenance
tmct> /exit

Point it at a repo's graph with tmct chat --repo /path/to/repo, or start with nothing — tmct bootstraps an empty memory and remembers what you tell it.

tmct init         # scaffold .tmct/, tmct.toml, seed corpus + provenance
tmct syllogise    # offline: pre-derive entailed facts (a maintenance job)

How it works

  • Multiple concurrent interpretation strategies per message — grammar parse, keyword picking, noise-word removal, fuzzy matching. Same-class results merge; distinct classes get an explicit “if you mean X then …” instead of a silent guess.
  • An ACE-inspired controlled grammar — text that fits it is compiled to OWL-labelled triples the graph memory can store and answer from.
  • Two-layer memory — an always-loaded OWL-labelled JSON graph (.tmct/, local, never committed) plus text blocks under a PageRank-style relevance index, both fed by every parsed exchange and by cleaned session logs. Committed corpuses (a ConceptNet slice is planned) seed the vocabulary.
  • Provenance & trust on every fact — each fact records where it came from and when; sources are first-class, and a deterministic, explainable trust score (source-type prior × corroboration × recency) weights retrieval by relevance × trust. When trusted sources disagree, /memory shows both sides with their provenance instead of silently picking one.
  • Negation & passive — “which modules do not import X” computes a bounded set complement (an honestly empty answer stays a miss); “imported by” and “imports” traverse opposite edges.
  • Response finishing — answers are segmented into prose vs protected spans (entities, paths, numbers, code, provenance); a small grammar pass touches prose only, under a guard that proves the protected spans pass through byte-for-byte.
  • Speculative inference, offline — tmct syllogise forward-chains the OWL subclass closure into low-trust, retractable entailed facts as a bounded maintenance job — never on the chat's hot path.

The repository interface

tmct builds no index of its own — it consumes a graph through a versioned (1.0.0), OWL-grounded, machine-readable service contract where a miss is a value, not a throw. It ships reference providers (fixture + empty/bootstrap graph) and a runnable conformance suite: any external producer (seonix first) runs the same suite to claim conformance. Conformance is the suite, not prose.

Security & supply chain

Offline and $0 means the supply chain has to be trustworthy too:

  • CI runs SAST and secret detection.
  • A nightly npm audit + OSV-Scanner job watches dependencies.
  • Releases publish with npm provenance.
  • A SECURITY.md policy documents coordinated disclosure.

The no-LLM, honesty pitch

  • No LLM, anywhere, ever — deterministic language libraries (wink-nlp's local model), template sets, and graph lookups. Offline. $0 per message.
  • Not an indexer — tmct consumes a graph via a provider seam; it builds no codebase index of its own.
  • Not a reasoning model — where it “reasons”, it calculates, and shows the calculation as prose.
  • Never guesses silently — a miss is declared, with a nudge toward a question it can answer. A wrong confident answer is treated as worse than an honest miss — that rule is wired into its eval rubric.

Roadmap

Phase 0

Reshape (v0.2.0 — done)

LLM fallback stripped, extraction stack and MCP server dropped, MPL-2.0, tmct naming, empty-graph bootstrap, published to npm.

Phase 1

Interpretation pipeline + memory foundations

The multi-strategy pipeline, the conversational memory graph, the graph-provider adapter contract, an OpenTUI shell.

Phase 2

Grammar → OWL + corpus

The ACE-inspired grammar emitting OWL triples, the tmct-core ontology, template libraries, a committed ConceptNet slice (CC-BY-SA 4.0).

Phase 3

Chat tuning cycle (autonomous)

A fixed chatbench case set, deterministic replay, LLM-as-judge scoring — in the offline eval harness only; the product stays no-LLM.

Provenance

Source-link & trust primitive (done)

Timestamped facts, first-class sources, deterministic trust, trust-weighted retrieval, contradiction surfacing in /memory.

Phase 6

Formulaic competence (done)

A technical (C1) register of templates and productive-vs-performance dual-banding in the benchmark.

Phase 7

Response finishing (done)

Typed-span segmentation with a protected-span invariance guard; the a/an fix is active, broader voice rules parked.

Phase 8

Repository interface (done)

A versioned, OWL-grounded service contract, reference providers, a conformance suite, and tmct init.

Phase 9

Speculative inference (done)

tmct syllogise — offline, bounded, deterministic forward-chaining into low-trust, retractable facts.
